# ABIT Maryland coefficient / distribution files — provenance

Generated by `build_coef.py` from the cleaned Regional Travel Survey (RTS,
`ABIT/input/rts/rts_tours.csv` + `rts_trips_clean.csv`, 57,627 tours / 163,290 trips) and the
Tour-Based MITO estimates (`Tour Based MITO/models/*/output/coefs_*.csv`). This is a **single
representative weekday** scenario for MATSim (24h), so weekly components are intentionally inert.

RTS purpose mapping: HBW→WORK, HBE→EDUCATION (school; bus+car-passenger dominated, confirms school
travel), HBS→SHOPPING, HBO/WBO→OTHER (split into RECREATION/ACCOMPANY/OTHER via trip d_activity
codes 10/16/18). RTS modes → ABIT Mode enum (autoDriver→CAR_DRIVER, autoPassenger/sr→CAR_PASSENGER,
bus→BUS, train→TRAIN, walk→WALK, bike→BIKE).

## Full published mode-choice model (Chayan & Cirillo 2024) — replaces share-replay
The tour mode choice is now the COMPLETE published model (`MarylandFullModeChoice`): 5 purpose-specific
MNLs, per-mode utility `V = ASC + b_age·age + b_male·male + b_lic·license + b_hhsize·hhsize +
b_hhautos·hhautos + b_core·coreCity + b_med·medCity + b_rural·rural + b_gc·GC + b_tl·tripLength`.
Reference alt = CAR_DRIVER. Modes [CAR_DRIVER, WALK, BIKE, CAR_PASSENGER, SHARED_RIDE, BUS, TRAIN];
SHARED_RIDE folds into CAR_PASSENGER for ABIT output; TRAM_METRO uses TRAIN's coefficients.

| File | Content | Source |
|------|---------|--------|
| `modechoice_published_{HBW,HBS,HBO,NHBW,NHBO}.csv` | full published slopes + ASCs | **PAPER** Table 3 (HBW) + A1–A4, read verbatim; cross-checked vs `ModeChoice` JS |
| `modechoice_full_{work,education,shopping,recreation,accompany,other}.csv` | published slopes + **re-anchored ASCs** | slopes = paper; ASCs iteratively re-anchored to `rt_mode_by_purpose.csv` (base no-toll shares) |

Purpose map: WORK/EDUCATION→HBW, SHOPPING→HBS, OTHER/RECREATION/ACCOMPANY→HBO, SUBTOUR→NHBW.

**Generalized cost:** `GC(min) = travelTime(min) + monetaryCost($)·60/VOT($/h)`. VOT: CAR_DRIVER/CAR_PASSENGER=30,
BUS/TRAIN=15, SHARED_RIDE=40. monetaryCost: auto 0.12/km, transit 0.50/km, walk/bike 0. NOTE: the ·60/VOT
converts $ to time-equivalent minutes — the literal $/VOT in the paper spec leaves the money term negligible
(dimensionless), i.e. price-INelastic; the ·60 makes the model genuinely price-elastic as required for the
I-695 toll study. The published GC coefficients (HBW AutoD −0.013, AutoP −0.035, Bus −0.03, Train −0.006,
etc.) are the paper's — the shipped `ModeChoice` JS had them numerically dead (~e−139), which is why that
build had no price response.

**TOLL HOOK:** `MarylandFullModeChoice.setToll($)` (default 0, property `auto.toll`) ADDS a per-run auto toll
to the auto monetary cost → flows through GC → mode shift. Structured so a per-OD/zone/link toll matrix can
replace the flat value. `RunTollTest` runs base vs $2 toll on the same population/ASCs → `output/toll_test.csv`.

**Adaptation (only this):** ASCs re-anchored via iterative calibration against the real generated tours
(`reapplyAndCalibrate`) so base shares reproduce the RTS tour shares. All published slopes kept.
